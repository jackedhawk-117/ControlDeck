# Gyro aiming — design notes (Milestone 6)

> **Status: design only.** Gyroscope input is not implemented in Milestones
> 1–2. This document records the agreed math and test plan so the Milestone 6
> implementation has a normative reference. The wire protocol does not change:
> only the resulting mouse deltas are transmitted.

The goal is console-style motion aiming (Switch/DualSense-like): large camera
movement on the touchpad, fine aim with the gyroscope, both feeding one mouse
pipeline. Raw sensor data never leaves the phone.

## 1. Sensors

| Sensor | Use |
|---|---|
| `TYPE_GYROSCOPE` (rad/s) | High-rate relative rotation for fine aim; needs bias correction |
| `TYPE_ROTATION_VECTOR` | Fused absolute orientation quaternion; stable yaw/pitch reference, recenter |
| `TYPE_GAME_ROTATION_VECTOR` (optional fallback) | Same without magnetometer; preferred indoors if the geomagnetic sensor is noisy |

All sensor callbacks run on a dedicated `SensorManager` listener; values are
copied into a pre-allocated mailbox (no allocation in the hot path). The mapper
runs on `Dispatchers.Default` at the display/input tick rate (target 120 Hz)
and only reads the latest mailbox snapshot.

## 2. Coordinate frames and recentering

1. Convert `TYPE_ROTATION_VECTOR` to a unit quaternion `q` (w, x, y, z), using
   the phone's current screen rotation (landscape) so "up" is consistent.
2. On recenter, store `q0 = q`. The working orientation is the relative
   rotation `qRel = q0⁻¹ · q`. This defines the neutral phone pose; it does not
   matter whether the phone is held flat or upright.
3. Extract yaw (rotation about the world up axis) and pitch (rotation about the
   phone's right axis) from `qRel`. Roll is computed but ignored by default.
4. Keep `lastYaw`/`lastPitch`; per tick compute wrapped differences:
   `dYaw = wrapPi(yaw - lastYaw)`, `dPitch = wrapPi(pitch - lastPitch)`.
   Wrapping prevents a ±π jump at the pole/turn boundary.

Recenter actions:

- Explicit Recenter button (cell action) → `q0 = current q`, `lastYaw/Pitch =
  current`, no emitted delta.
- Optional auto-recenter when a hold activation button is released. On
  activation, reset `lastYaw/Pitch` to the current orientation so there is no
  jump; on release, optionally store a new neutral.
- Never emit a delta on the frame that recenters.

## 3. Gyro path (high-rate fine aim)

For each tick `dt`:

1. Read angular velocity `ω = (gx, gy, gz)` in rad/s.
2. Subtract the calibrated bias `b` captured at rest (per profile).
3. Apply a small deadzone `|ω| < dz` → 0 to suppress hand tremor.
4. Rotate `ω` into the world/neutral frame using `qRel` (or the full `q` and
   then subtract the recenter reference) so horizontal rotation always means
   yaw regardless of how the phone is held.
5. Optionally pass yaw/pitch rates through a one-euro filter
   (`fcmin`, `beta`, `dcutoff`) for smooth low-speed aim without adding
   perceptible lag at high speed.
6. Convert to pixels:
   `pixels = rad * sensitivityDegPerCount * pixelsPerDegree * dtScale`.
   Sensitivity is per axis, per profile; ADS can use a separate multiplier.
7. Accumulate into the shared Q16.16 mouse accumulator, clamp per tick
   (e.g. ±200 px) to reject spikes, and emit one `MOUSE_REL` event with the
   integer part, keeping the fractional remainder.

Why not map raw accelerometer? Accelerometer measures gravity + linear
acceleration, so it cannot distinguish tilt from translation and is unusable
for aim. Orientation must come from the fused rotation vector and/or integrated
gyroscope.

Alternative/complementary path: integrate `q` from gyroscope samples between
rotation-vector updates (gyro is fast, rotation vector is drift-free but
slower). On each rotation-vector update, blend/slerp back to the absolute
reference, with a small correction gain to avoid visible snaps.

## 4. Touchpad path

The touchpad region reports relative finger movement in pixels; apply its own
sensitivity/acceleration/smoothing/inversion, then add its delta to the same
per-tick accumulator as the gyro path. Both sources are summed before the
Q16.16 conversion, so neither can overwrite or stall the other.

## 5. Activation modes

| Mode | Behavior |
|---|---|
| Always | Gyro contributes whenever a session is active |
| Hold | Contributes only while the assigned cell is held; optional auto-recenter on release |
| Toggle | Cell toggles on/off; recenter on enable to avoid a jump |
| Region | Contributes only while a finger is inside the configured screen region |

Activation changes reset `lastYaw/Pitch`; deactivation flushes any pending
accumulated delta once, then stops contributing. No delta is generated by the
activation transition itself.

## 6. Configuration (per profile)

- Enable/disable yaw and pitch; roll disabled by default (optional roll→wheel).
- Horizontal and vertical sensitivity; invert X/Y.
- Deadzone, smoothing (one-euro parameters), max pixels per tick.
- Normal and ADS sensitivity multipliers.
- Activation mode + activation cell; recenter cell; auto-recenter flag.
- Gyro bias calibration values and recenter quaternion reference.

## 7. Testing plan

Unit tests (JVM, no device):

- Quaternion relative/orientation math with synthetic rotations (90°, 180°,
  ±π wrap, gimbal-edge poses).
- Yaw/pitch extraction and sign conventions for all four landscape
  orientations.
- Recenter produces zero delta and no jump; auto-recenter on release.
- Deadzone, inversion, sensitivity scaling, ADS switching.
- Accumulator Q16.16: slow motion below one pixel still accumulates; clamping
  rejects spikes.
- Hybrid fusion: touchpad + gyro deltas sum exactly once per tick.

On-device (Milestone 7):

- Hold a neutral pose for 60 s: drift must stay below a few pixels.
- Recenter while aiming: no visible snap.
- Toggle rapidly: no residual movement after deactivation.
- Simultaneous touchpad + gyro while holding fire and movement keys.
- Compare in-game sensitivity at 60/90/120 Hz display modes.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Gyro bias/drift | At-rest calibration, rotation-vector correction, recenter |
| Sensor timestamp jitter | Use `SensorEvent.timestamp` for dt, clamp dt to a sane range |
| Magnetic interference | Prefer game rotation vector when available; make source configurable |
| Phone held at steep pitch | Quaternion yaw extraction with wrap handling; axis remap options |
| Latency | Sensor listener + mapper at display rate; no allocations; Q16.16 batching |
| Different phone axes | Apply `SensorManager.remapCoordinateSystem` from display rotation before mapping |
